# KArSL 502 research handoff status

**Technical update:** This code branch now includes a hash-pinned Python 3.12/Linux CPU environment, standalone centroid and linear baseline training/verification, the original 07 audit notebook, an experiment log, a controlled checkpoint manifest, and a research-only CV/NLP candidate interface. Both historical baselines were re-evaluated on the complete frozen train/validation PASS population with exact validation metric agreement. A separately versioned new linear 30-epoch CPU run is recorded in `baseline_replay_502.md`. The video adapter was rechecked on original frames and prior 12/20-pair diagnostics are packaged; these do not establish confirmed-sign recognition.

**Date:** 2026-10-26. The project owner stated that use of the KArSL data is permitted and that the disputed labels have been reviewed and are acceptable for this research handoff. This records the team's decision; the branch does not contain the original permission terms, reviewer identity, or sample-level sign-off. The frozen source class IDs and model label mapping have not been changed or retrained in response.

This branch now contains preprocessing, training, calibration, evaluation, prediction, notebooks, tests, aggregate reports, the selected CNN and comparison GRU weights, calibration config, and source label mapping. A clean checkout can load and run the frozen model. Source Pose files, original videos and feature shards remain at their dataset source/storage for any retraining work.

The selected CNN was chosen by validation macro F1 over the GRU baseline. Full train/validation replays and the frozen calibration/test replay matched the recorded experiments. The primary frozen test has 24,536 samples from 500 represented true classes, 52.5187% accuracy, 0.485208 macro F1, and 74.2908% top-5 accuracy. Historical test exposure and the excluded class-27/28 examples still limit the interpretation. Acceptance coverage is 0%, so the prediction interface returns `uncertain` and the top-k list is advisory. No validated unknown-sign set or production CV-to-model integration is claimed.

The earlier audits in this directory preserve their dated findings and open questions as they were recorded. The project owner's later statements resolve the team's branch handoff decision on usage and label review; they are not an independent audit of upstream rights, gloss semantics, or individual video/Pose identity. Those distinctions matter if the team later publishes model weights, source derivatives or a camera-based translation claim.

The original preprocessing, model, experiment and replay Python files are byte-fingerprinted by the research artifacts, so the repository Ruff configuration excludes those exact frozen paths from automatic style changes. The release suite now requires the committed checkpoint and verifies loading plus the synthetic Pose prediction on a clean checkout. A separate CV environment successfully extracted finite `(32,150)` features from 15 original frames. The workflow installs the pinned CPU lock and repeats the full release suite.
